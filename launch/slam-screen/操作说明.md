# 四画面实时录制

Windows 保留 Isaac Sim 原来的 Aisle view。Ubuntu 运行这个显示器，窗口中上方为在线占据地图，下方为同一次运行的 RGB 与机身前向雷达点云。Windows OBS 同时录到 Isaac Sim 与 VMware 两个窗口，得到四画面录像。

## 安装与启动

把 slam-screen.zip 传到 Ubuntu 的 /home/flora/as2_slam/，执行以下命令。

```bash
cd ~/as2_slam
unzip -o slam-screen.zip
sudo apt update
sudo apt install -y python3-tk python3-pil.imagetk python3-numpy
bash ~/as2_slam/slam-screen/start-screen.sh
```

解压目录为 slam-screen。脚本导入 ROS 2 Humble，指定 Fast DDS 与 domain 0，并检查依赖和渲染函数。此界面只订阅话题。窗口可在启动 SLAM 前打开，显示 Waiting 或空的各视图，收到数据后更新。

图形界面启动后关闭先前额外打开的 RViz。将 VMware 来宾分辨率调至至少 1024x900，或在 Ubuntu 设置中把缩放设为 100%，再将 AS2 SLAM Live Screen 窗口最大化。显示器会按窗口宽高缩放地图和图像。

Windows 启动 launch/four-aisle-slam.bat。Ubuntu 另开终端执行 bash ~/as2_slam/start-one-path-live.sh，沿用两次已验证的配置。录制前检查 Ubuntu 剩余磁盘和 Windows 录像盘空间。SLAM 预检仍检查 2 GiB 可用空间。

## OBS

将 Windows 桌面上的 Isaac Sim 放在左侧约 60%，VMware 放在右侧约 40%。两者同时可见并保持视图展开。OBS 的显示器采集录下这个完整屏幕。建议先以 1920x1080、15 FPS 录 10 秒并回看小字和卡顿情况；资源不足时降至 1280x720。选择可用硬件编码器，录像保存到 Windows E 盘。

最终布局为左侧机器狗主画面；右侧上方在线地图；右侧下方两个并排框分别为 RGB 与雷达。共四块画面，同一次屏幕录制。保留 Isaac 状态中的仿真秒数和右侧 SIM 秒数。首次接收、网络与地图发布存在短暂延迟，各传感器框还显示自身采样时间。

OBS 开始录像后再启动 SLAM，保留空地图到出发建图的过程。若 SLAM 已启动，直接录制其后的真实过程。后期对合成的整幅视频统一加速或剪辑，并标注倍率及片段拼接。

## 颜色与数据含义

- Map 的白色为已观测空闲区，黑色为占据区，灰色为未知区域。
- 蓝线为 RTAB-Map 当前 mapGraph 中各节点位置按消息顺序的连线，地图回环优化时会更新。它属于 SLAM 图节点轨迹。
- 红点与朝向线来自 map 到 base_stabilized 的估计 TF。TF 尚未就绪时不显示红点。
- RGB 直接显示 /as2/camera/image_raw。颜色判别、录制不读取理想深度。
- 雷达只显示 /as2/lidar/points 当前扫描，按 X 前、Y 左、Z 上的传感器坐标投影为前视图，向下俯视 10°，水平视角约 100°。点的颜色按相对高度变化。原始点云为 360°扫描，这里只把前向视野投影到屏幕。
- SIM 是 /clock 仿真时间；RGB 与雷达标题中的 t 是消息采样时间；received 表示距上次收到消息的墙钟秒数。
- Global events 是实时桥接统计。最终运动时段与几何合格回环数仍用保存数据库审计。

## 快速检查

1. 首先确认 RGB 与雷达连续更新，t 递增，received 通常小于约 2 秒墙钟时间（仿真约四倍慢速运行）。
2. 地图开始时只出现已扫描的一块，机器狗前进后逐步扩展。地图发布频率较低，稍晚于传感器画面更新。
3. 狗转向时 RGB 视野与雷达前视方向同时变化，地图中的位置和路径跟随更新。
4. 若某框空白，保留终端错误并检查 ros2 topic list。界面与 ROS 必须在同一个 Ubuntu 桌面会话运行。

运行结束先停止 OBS，Ubuntu 的 SLAM 终端 Ctrl+C 保存数据库，最后关闭显示器窗口。显示器不会停止 SLAM 管线。

本包已做点云解码、地图渲染和前视投影自检。尚需在用户的 Ubuntu / ROS 实际运行中核验显示、资源占用与订阅效果。
