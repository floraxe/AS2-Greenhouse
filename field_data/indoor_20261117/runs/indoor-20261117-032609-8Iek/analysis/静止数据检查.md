# 首次室内静止采数检查

原始包 SQLite 完整性检查通过，31.55 秒，659.6 MiB。原始包 SHA-256 为 dc7903fa0dadda392e9255a0f39d3c10462e118b089aee968e1cc1243ceb04b9。

点云 245 条，每帧约 10.69 万点，本包所有 XYZ 点均为有限值，frame_id 为 hesai_lidar。相邻传感器时间戳的中位间隔约 0.10006 秒，最大 1.00002 秒。点云仅覆盖包起点至约第 26.2 秒，需检查末段点云停止及中途间断。

IMU 5326 条，frame_id 为 hesai_lidar，相邻采样间隔中位数 0.005058 秒，约 198 Hz，最大间隔 0.36004 秒。静止加速度模长均值 9.733 m/s²，角速度模长均值 0.00272 rad/s。加速度均值向量约 [-1.045,9.599,-1.219]，说明 IMU 发布坐标轴与机身前左上存在旋转，不能直接套用仿真外参。

两路标准消息严格解码通过。传感器头时间约为 926 至 957 秒，录包接收时间为 Unix epoch，二者时间原点不同，差值不能当成网络延迟。相机时间映射仍待核验。

视频 802 条实际混合了 720 与 360 两路载荷。当前数据推断的消息结构为 uint64 时间、uint32 分辨率、uint8 序列，全部载荷长度吻合。它与压缩包旧 Go2FrontVideoData.msg 不一致。抽出 720 路 H.264 后成功解出 1280×720 RGB 图，见 front_rgb.png。开始接收位于视频预测帧中，FFmpeg 初始报告缺 PPS，收到后续参数和关键帧后可解码。

机体状态消息 535 条比旧定义多 280 字节，旧 stamp 前缀为零。按旧布局解出的位姿和姿态仅作为排查线索，尚未验证实际固件布局。实机自主控制前需确认匹配的宇树消息定义，原始 bag 保留完整载荷。

下一步可用原厂遥控器录短距离人工直行，重点验证坐标方向与时间戳，不启用旧版自主巡航。建议静止3秒、低速直行约2米、停稳3秒；实际时长依人工操作，空间不足时缩短距离并记录实测值。沿用四路点云、IMU、状态和视频；机载 /uslam/frontend/odom 本包未收到。先把数据传回 Windows，结合末段点云间断进行对照分析。
